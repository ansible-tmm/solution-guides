# Claude Code instructions (solution-guides)

Follow repository conventions in `.cursor/rules/` when editing markdown solution guides.

## Automation orchestrator (required spelling)

In **new or revised prose**, write **Automation orchestrator** (lowercase **o** on orchestrator). Do not use **Automation Orchestrator** except when quoting an external document or UI label literally.

- Good: "Automation orchestrator adds approval gates above AAP job execution."
- Bad: "Automation Orchestrator adds approval gates..."

Abbreviation: **Automation orchestrator (AO)**, then **AO** in the same section.

Full rule: [.cursor/rules/red-hat-automation-orchestrator-terminology.mdc](.cursor/rules/red-hat-automation-orchestrator-terminology.mdc)

## Red Hat Lightspeed vs AI playbook authoring

- **Red Hat Lightspeed** (console.redhat.com): CVE, Advisor, Remediations -- **Red Hat-curated**, approved Ansible content. Do not write "generated by Red Hat Lightspeed" (implies AI). Prefer **curated remediation playbooks from Red Hat Lightspeed**.
- **Automation code assistant**: LLM-assisted **authoring** in the IDE -- distinct from Lightspeed remediations.

Full rule: [.cursor/rules/red-hat-lightspeed-terminology.mdc](.cursor/rules/red-hat-lightspeed-terminology.mdc)
